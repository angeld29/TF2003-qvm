# TF2003-qvm

**QuakeWorld Team Fortress 2003** — серверный Team Fortress-мод для QuakeWorld на C,
собирается в два артефакта:

- **Нативная shared-библиотека** `qwprogs.so` / `qwprogs.dll` (`sv_progtype 1/3`);
- **QVM-байткод** `qwprogs.qvm` (`sv_progtype 2`) — один платформонезависимый бинарник.

Запуск на серверах **mvdsv** и **qwsv262**. Это активный разрабатываемый мод воркспейса QWTF
(сестринский read-only форк — `TF2003-qvm-hammer`).

> Английская версия: [README.md](README.md).

## О проекте

- Игровая логика — обычный C, компилируемый дважды: нативно (`add_library(SHARED ...)`) и через
  `q3lcc` → `game.q3asm` (QVM). Оба пути сборки должны оставаться зелёными
  (см. `docs/adr/0001-tf2003-build.md`).
- Map-сущности описаны в таблицах `src/g_spawn.c` (`field_t fields[]`, `spawn_t spawns[]`).
- Расширения API движка — только через механизм `G_Map_Extension` (слоты ≥ 256), **не** новыми
  значениями экспорт-энума: реализовано в `src/g_ext.c` / `include/g_ext.h`
  (16 расширений, слоты 256–271; см. `docs/adr/0005-g-map-extension.md`).
- Поддержка CSQC: серверная часть `src/g_csqc.c` / `include/g_csqc.h` с экспортами
  `GAME_EDICT_CSQCSEND` / `GAME_QCREQUEST` (см. `docs/adr/0007-csqc-ssqc-data-flow.md`),
  клиентский модуль в `csqc/` → `csprogs.dat` (план: `docs/tf2003_csqc_client_plan.md`).
- `GAME_API_VERSION` находится в `include/g_public.h`; при запуске на более старом движке мод
  завершается с ошибкой (`src/g_main.c`).

| Путь | Содержимое |

| `src/` | исходники мода (`g_main.c`, `g_spawn.c`, `g_ext.c`, `g_csqc.c`, …) |

## Ограничения разработки

Жёсткие правила для правок этого кода — читать перед изменением.

### Hard rules

- **Не менять `include/progdefs.h`** (автогенерируемый: «generated by qcc, do not modify») и
  **`include/g_public.h`** (контракт с движком). Расширение экспортов/импортов — только через
  `G_Map_Extension` слоты ≥ 256 (`docs/adr/0005-g-map-extension.md`), не новыми значениями энума.
- Использовать `PROG_TO_EDICT` / `EDICT_TO_PROG` для доступа к полям сущностей
  `(gedict_t)->s.v` (например, `.owner`, `.enemy`).
- Таблицы map-сущностей — в `src/g_spawn.c` (`field_t fields[]`, `spawn_t spawns[]`).
- Спавн ракет требует `g_globalvars.newmis`.
- Не использовать команду `map` вместе с `redirectcmd`, `executecmd`, `readcmd`.
- Не смешивать строковые массивы и другие типы в одной структуре (q3asm кладёт строки в
  отдельный сегмент).

### Квирки компилятора / QVM

> Полный список ниже — каноничный контракт. Полные детали сборки см. `docs/adr/0001-tf2003-build.md`.

- **`double` не существует**, всё 32-битное; `float` не проходит type promotion при передаче
  параметром.
- Для целочисленных типов избегать всего, кроме `int`. Конкретно: вообще не использовать `short`
  и `unsigned char` (info from ID). Q3VM и компилятор плохо работают с типами не-словного
  размера — часто это даёт непредсказуемое поведение.
- `switch` иногда генерирует небезопасный код при run-on в `case`-метках: у каждой `case`-метки
  должен быть собственный `break` **либо** ноль строк логики до следующей `case`-метки.

### Endianness Mac VM

Mac VM — big endian (старший байт первым в int и short), поэтому аккуратно с I/O-операциями.
Например, нельзя сериализовать `int` в файловый поток простой записью его байтов
(`trap_FS_Write(&i, 4, f)` при `int i` даст другой результат на Mac VM, чем на PC VM).

Извлечение байтов сдвигами и запись во временный буфер работает. Либо написать собственный
`htonl()` и т.п. (Легко проверить, нужен ли swap: присвоить `int` константу, взять `char*`
на него и посмотреть байты.)

## Syscall-плумбинг

Новый вызов движка затрагивает три файла, которые должны быть в синке:

- `include/g_syscalls.h` — прототипы;
- `src/g_syscalls.c` — нативные трамплины (только DLL);
- `src/g_syscalls.asm` — QVM `equ`-номера (используется вместо `.c` под `Q3_VM`).

## Добавление исходника

Добавить файл в `SOURCE_LIB` в `CMakeLists.txt` — этого достаточно и для native, и для QVM
(список модулей `game.q3asm` генерируется на конфигурации). **Не** трогать `meson.build`: это
устаревшая нативная вторичная сборка, рассинхронизирована с `SOURCE_LIB`.
Подробности: `docs/adr/0001-tf2003-build.md`.

## Сборка и запуск

- Платформенные требования — `BUILD.md`. Процесс сборки и объём бинарной сборки по задаче —
