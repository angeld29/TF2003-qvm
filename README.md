# TF2003-qvm

**QuakeWorld Team Fortress 2003** — a server-side Team Fortress mod for QuakeWorld, written in C
and dual-compiled into two artifacts:

- **Native shared library** `qwprogs.so` / `qwprogs.dll` (`sv_progtype 1/3`);
- **QVM bytecode** `qwprogs.qvm` (`sv_progtype 2`) — one platform-independent binary.

Runs on **mvdsv** and **qwsv262** servers. This is the active development mod of the QWTF workspace
(sibling read-only fork: `TF2003-qvm-hammer`).

## Project overview

- Gameplay code is plain C compiled twice: natively (`add_library(SHARED ...)`) and through
  `q3lcc` → `game.q3asm` (QVM). Both paths must stay green (see `docs/adr/0001-tf2003-build.md`).
- Map entities are described in `src/g_spawn.c` tables (`field_t fields[]`, `spawn_t spawns[]`).
- Engine API extensions go through the `G_Map_Extension` mechanism (slots ≥ 256), *not* new export
  enum values — implemented in `src/g_ext.c` / `include/g_ext.h`
  (16 extensions, slots 256–271; see `docs/adr/0005-g-map-extension.md`).
- CSQC support: server-side `src/g_csqc.c` / `include/g_csqc.h` with exports
  `GAME_EDICT_CSQCSEND` / `GAME_QCREQUEST` (see `docs/adr/0007-csqc-ssqc-data-flow.md`),
  client module in `csqc/` → `csprogs.dat` (plan: `docs/tf2003_csqc_client_plan.md`).
- `GAME_API_VERSION` lives in `include/g_public.h`; the mod aborts at load on an older engine
  (`src/g_main.c`).

## Development constraints

These are hard rules for editing this codebase — read them before changing code.

### Hard rules

- **Do not modify `include/progdefs.h`** (auto-generated: “generated by qcc, do not modify”) or
  **`include/g_public.h`** (engine contract). Extending exports/imports goes through
  `G_Map_Extension` slots ≥ 256 (`docs/adr/0005-g-map-extension.md`), not new enum values.
- Use `PROG_TO_EDICT` / `EDICT_TO_PROG` to access `(gedict_t)->s.v` entity fields
  (e.g. `.owner`, `.enemy`).
- Map entity tables live in `src/g_spawn.c` (`field_t fields[]`, `spawn_t spawns[]`).
- Missile spawn requires `g_globalvars.newmis` set.
- Don't use `map` command with `redirectcmd`, `executecmd`, `readcmd`.
- Don't use string arrays in one structure with other types (q3asm places strings in a separate
  segment).

### Compiler / VM quirks

> Full list below is the canonical contract. If in doubt, verify against how the QVM toolchain
> handles the construct — see also `docs/adr/0001-tf2003-build.md` for build specifics.

- **`double` does not exist**, everything is 32-bit; `float` does not undergo type promotion when
  passed as a parameter.
- For integer types avoid using data types other than `int`. Specifically don't use the `short` or
  `unsigned char` data types at all (info from ID). The Q3VM and compiler do not deal with
  non-wordsize types well — using them often results in unpredictable behaviour.
- `switch` statements sometimes produce unsafe code if you use run-on in `case` labels, i.e. each
  `case` label must have its own `break` statement **or** no lines of logic between the next
  `case` label.

### Mac VM endianness

The Mac VM is big endian (high byte first in integers and shorts), so be careful with certain I/O
operations. For example, you can't serialize an integer to a file stream just by writing its bytes
(`trap_FS_Write(&i, 4, f)` — if `i` is an `int` — produces different results in the Mac VM than in
the PC VM).

Extracting bytes using shift operators and writing them to a temporary buffer works. Or write your
own `htonl()`, etc. (It's easy to tell if you need to swap bytes: assign an `int` to a constant,
get a `char*` pointer to it, and check the bytes.)

## Syscall plumbing

A new engine call touches three files that must stay in sync:

- `include/g_syscalls.h` — prototypes;
- `src/g_syscalls.c` — native trampolines (DLL only);
- `src/g_syscalls.asm` — QVM `equ` numbers (used instead of the `.c` under `Q3_VM`).

## Adding a source file

Add it to `SOURCE_LIB` in `CMakeLists.txt` — that feeds both the native build and the generated
QVM module list `game.q3asm` (regenerated on configure). Do **not** touch `meson.build`: it is a
stale native-only secondary build, out of sync with `SOURCE_LIB`. Details: `docs/adr/0001-tf2003-build.md`.
